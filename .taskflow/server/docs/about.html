About TaskFlow

TaskFlow is a structured, database-driven development pipeline for VS Code + GitHub Copilot.

It gives your AI agents a shared memory, a defined process, and clear roles. Instead of one agent doing everything in one long chat, each development activity is handled by a specialist agent, at the right step, with the right context, and only when the previous step is approved.

Task-Driven Architecture

Every step in the pipeline — defining features, writing tests, building, reviewing, documenting — is represented as a row in the tasks table. An agent can only write output for a step if it holds a valid claim on that task. Once it submits, the task advances; the next agent in the sequence picks up from the database, not from the chat.

This solves two common failure modes of Copilot agents:

  • Stale, over-broad context: each agent calls read_task_context and receives a scoped payload assembled for that step only.
  • No audit trail: every decision, approval, retro, and test result is written to the database, not buried in chat history.

Review Gates

TaskFlow applies a dedicated reviewer agent to every major output before the pipeline can advance:

  • PM Reviewer approves the feature set (step 4) before any build work begins, and performs final verification at step 13.
  • Test Reviewer approves test specs (step 6) before the Builder is authorised to implement.
  • PM Reviewer approves decisions (step 11) before they are formalised as decision artefacts.

Key Features

Zero Install

VS Code detects .vscode/mcp.json on startup and launches the MCP server via uv automatically.

Shared Brief

Every agent draws from the same structured brief stored in the database, not from re-reading files or chat history.

Autonomous by Default

The Orchestrator runs the entire pipeline hands-off. But every step can also be invoked directly.

Built-in Retry

If a task fails three times it becomes blocked and the Orchestrator escalates. You can also reset or force-advance tasks.

Cycling Pipeline

Steps 5–13 repeat per feature. New-feature recommendations feed back into step 3 as the next cycle's backlog.

Control Plane

This dashboard gives you full visibility and control: approve, reject, pause, resume, and answer agent questions.

Agents & Roles

Agent Steps Role
Project Initiation Manager Pre-pipeline Creates project brief conversationally or ingests a brief JSON file
Dev Manager Pre-pipeline Configures MCP servers, skills, and agent capabilities for the tech stack
Orchestrator 3–13 Runs the full pipeline autonomously; retries on failure; escalates when blocked
Product Manager 3, 10, 12 Defines features + DoD; writes decisions; formalises decision artefacts
PM Reviewer 4, 11, 13 Approves features, decisions, and final verification
Tester 5, 8 Writes test specs per feature; executes tests against the build
Test Reviewer 6 Approves test specs before any build work is authorised
Builder 7 Implements features against approved test specs; the only agent with file access
Documenter 9 Writes feature retrospective and seeds recommendations
