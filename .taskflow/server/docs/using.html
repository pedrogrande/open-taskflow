Using TaskFlow

TaskFlow has three phases: Initiate, Configure, and Run.

1. Initiate: build the project brief

The project brief is the foundation. All agents draw context from it throughout the pipeline. There are two ways to create one:

Option A: Project brief form (recommended)

Open .taskflow/project-brief-form.html in any browser, or use the New Brief page in this dashboard. Complete all sections: identity, goals, features, workflows, NFRs, integrations, risks, and timeline. Click Submit to TaskFlow — the data is ingested directly into the database.

Option B: Conversational brief

Use the slash command /start-project in VS Code Copilot chat. The Project Initiation Manager guides you through the brief one question at a time, recording each answer to the database.

2. Configure: set up the agent team

Once the brief is ingested, use /setup-team. The Dev Manager reads your brief, extracts your tech stack and integrations, and configures MCP servers, skills, and model preferences for your project.

3. Run: the pipeline

Start the full pipeline with /run-pipeline. The Orchestrator works through steps 3–13 one feature at a time. You can also use /my-tasks at any point to see what's pending.

The Pipeline (Steps 3–13)

Step Agent Output Gate
3 Product Manager Features + DoD → step 4
4 PM Reviewer Feature approval → step 5 × N features
5 Tester Test specs → step 6
6 Test Reviewer Test spec approval → step 7
7 Builder Build report → step 8
8 Tester Test results fail → step 7; pass → step 9
9 Documenter Retro + recommendations auto → step 10
10 Product Manager Decisions → step 11
11 PM Reviewer Decision approval → step 12
12 Product Manager Decision artefacts → step 13
13 PM Reviewer Final verification → step 3 (next cycle)

Dashboard Controls

This dashboard is your control plane for the pipeline. Here's what you can do:

  • Claim — Mark a pending task as in-progress
  • Approve ✓ — Mark an in-progress task as done and spawn the next step(s)
  • Reject ✗ — Reject a task with feedback; re-creates the worker task
  • Pause ⏸ — Pause a task or project; paused tasks are skipped by agents
  • Resume ▶ — Resume a paused task or project
  • Reset ↻ — Reset a blocked or rejected task to pending (retry_count = 0)
  • Run ▶ — Open VS Code with the appropriate agent pre-filled for this task
  • Answer questions — When agents need human input, answer directly from the Questions tab

Slash Commands

Command Description
/start-project Start a new project (brief ingestion)
/setup-team Configure the agent team for your tech stack
/run-pipeline Run the full pipeline autonomously
/my-tasks Show pending tasks for any agent role
/pipeline-status Show current pipeline state
/dashboard Open this dashboard
/onboard Onboard an existing project

Adding TaskFlow to an existing project

If you already have a codebase, use /onboard to scan your workspace, detect existing agents, skills, MCP servers, and tech stack, then guide you through creating a brief that captures what's already built.
